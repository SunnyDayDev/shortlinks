## Context

Greenfield-проект: пустой каталог `shortlinks/`, не git-репозиторий. Есть детальный
макет из Claude Design (`_design/Одноразовые ссылки.dc.html`) — нативный macOS-UI с
полной логикой (модель ссылки, генерация slug, статусы, тексты) и кастомной схемой
`sl://link/<slug>`. Утверждён план (`~/.claude/plans/floofy-moseying-karp.md`).

Ограничения, согласованные с пользователем:
- Бесплатный Apple ID (нет Apple Developer Program) → entitlements iCloud/CloudKit и
  App Sandbox недоступны/нежелательны.
- Формат: меню-бар + окно; плюс CLI.
- Синхронизация: файловая через iCloud Drive.
- Сборка: Xcode установлен.

## Goals / Non-Goals

**Goals:**
- Один Xcode-проект с тремя таргетами; вся доменная логика в общем `ShortlinksCore`,
  переиспользуемом приложением и CLI (без дублирования).
- Регистрация и постоянная (онлайн через макет) обработка ссылок без HTTP-сервера —
  через схему `sl://`.
- Опциональная синхронизация между Mac'ами на бесплатном Apple ID.
- Готовое окружение: git + GitHub, `.gitignore`/`README`/`CLAUDE.md`, настройка агента.

**Non-Goals:**
- CloudKit/record-level sync, iOS-таргет, распространение вне локального запуска,
  нотаризация/Gatekeeper-подпись, аналитика, многопользовательность.

## Decisions

- **Схема `sl://` вместо локального HTTP-сервера.** Так задано макетом и это нативный
  путь: Launch Services маршрутизирует открытие в приложение, не нужен запущенный
  сервер/порт. Альтернатива (localhost-сервер) отвергнута: работает только при
  запущенном процессе, конфликты портов, хуже UX. CLI резолвит/открывает через то же
  ядро.
- **Единый JSON-файл `links.json` со всеми ссылками (по выбору пользователя), а не
  SQLite и не файл-на-ссылку.** SQLite в iCloud Drive повреждается (WAL/частичная
  синхронизация). Единый файл проще файла-на-ссылку (одно место, тривиальный бэкап,
  меньше мусора в iCloud) ценой более широкой поверхности конфликтов. Чтобы не терять
  правки при параллельной записи app+CLI, все изменения — координированное
  read-modify-write под `NSFileCoordinator` с атомарной записью (temp+rename).
  Слежение — FSEvents/`DispatchSource`. Конфликтные версии iCloud сливаются по `id`
  ссылки (см. ниже).
- **iCloud Drive-файл вместо ubiquity-контейнера/CloudKit.** Официальные iCloud-API
  требуют платных entitlements. Файл `com~apple~CloudDocs/Shortlinks/links.json` —
  обычный путь в домашней директории; несендбоксенное приложение и CLI пишут туда
  напрямую, демон iCloud Drive синхронизирует. Бесплатно, без provisioning.
  Синхронизация опциональна (тумблер в Настройках).
- **Общий `ShortlinksCore` (framework) + App Group не используем.** App Groups требуют
  provisioning/sandbox. Общий путь хранилища (одинаково вычисляемый в обоих таргетах)
  убирает эту зависимость; CLI и app делят данные через файловую систему.
- **XcodeGen (`project.yml`).** Декларативная, ревьюабельная спека проекта; `.xcodeproj`
  генерируется и не коммитится. Альтернатива (ручной `.pbxproj`) хрупкая и плохо
  читается в диффах. CLI-зависимость `swift-argument-parser`.
- **SwiftUI `MenuBarExtra` + `Window`, `ActivationPolicy.accessory`.** Современный путь
  для меню-бар + окно (macOS 14+), без AppKit-боилерплейта; окно по требованию.
- **Пароль → соль+SHA-256 (`CryptoKit`).** Локальный гейт перед редиректом; открытый
  пароль не хранится. (В макете — лишь флаг.)
- **Одноразовая по умолчанию «сгорает» (`viewed`), удаление — опция.** Мягкая пометка
  надёжнее для файловой синхронизации, чем жёсткое удаление; ранний выбор пользователя
  «удалять» сохранён как переключатель в Настройках.
- **Подпись — самоподписанным сертификатом (manual signing).** Без Apple Developer
  Program: в `project.yml` для app-таргета `CODE_SIGN_STYLE: Manual`,
  `CODE_SIGN_IDENTITY` = самоподписанный сертификат из Keychain (создаётся через
  Keychain Access → Certificate Assistant), без provisioning profile. Альтернативы
  отвергнуты: «Apple Development» требует аккаунта-команды; ad-hoc (`-`) теряет подпись
  при перезапуске и хуже для постоянного обработчика схемы. Самоподписанный cert даёт
  стабильную идентичность для Launch Services и доступа к Keychain. Энтайтлменты не
  нужны (нет sandbox/iCloud-capability). CLI-таргет подписи не требует.
- **Окружение агента.** В репозитории — `CLAUDE.md` (контекст проекта, команды сборки,
  карта модулей) и проектные навыки/инструкции под Swift/macOS-разработку; `.gitignore`
  исключает `*.xcodeproj`, `DerivedData`, `.DS_Store`, артефакты сборки.

## Risks / Trade-offs

- **Конфликт единого файла при синхронизации / параллельная запись app+CLI** →
  координированное read-modify-write под `NSFileCoordinator` + слияние конфликтных
  версий iCloud по `id` ссылки (per-link merge), не теряя записи с разных устройств.
- **Гонка одноразовой при синхронизации** → merge-правило «viewed важнее active,
  ранний `consumedAt` выигрывает» + документирование остаточного окна.
- **iCloud Drive может «выгружать» файл (dataless)** → координированный доступ и при
  необходимости принудительная докачка; объём данных мал, риск низкий.
- **Несендбоксенное приложение с самоподписанным сертификатом** → Gatekeeper при
  распространении на другие машины (потребует ручного разрешения); вне scope — целевой
  сценарий локальный запуск/сборка из Xcode на машинах пользователя.
- **Кастомная схема работает только на Mac с установленным приложением** → ожидаемо;
  синхронизация данных через iCloud, резолв — локально на каждом устройстве.
- **Lost update при одновременной записи в один файл** → каждое изменение читает
  актуальный файл, применяет правку и атомарно перезаписывает (temp + rename) внутри
  одной координированной транзакции `NSFileCoordinator`.

## Migration Plan

Нечего мигрировать (первичный заход). Откат — удаление каталога данных и репозитория.
Деплой: `brew install xcodegen` → `xcodegen generate` → сборка/запуск из Xcode;
регистрация схемы происходит при первом запуске.
