## ADDED Requirements

### Requirement: Регистрация обработчика схемы
Приложение SHALL регистрироваться обработчиком URL-схемы `sl` в macOS (через
`CFBundleURLTypes`). Настройки SHALL позволять заявить приложение обработчиком по
умолчанию (`LSSetDefaultHandlerForURLScheme`).

#### Scenario: Регистрация при запуске
- **WHEN** приложение запускается впервые
- **THEN** macOS направляет открытие `sl://…` в это приложение

#### Scenario: Тумблер обработчика
- **WHEN** пользователь включает тумблер «Обработчик схемы sl://»
- **THEN** приложение становится обработчиком по умолчанию для схемы `sl`

### Requirement: Поток подтверждения перехода
При открытии `sl://link/<slug>` система SHALL найти ссылку и показать оверлей
перехода с тремя состояниями: подтверждение (`ready`) для активной ссылки,
заблокировано (`blocked`) для просмотренной/истёкшей, выполнено (`consumed`) после
перехода по одноразовой. По подтверждению цель SHALL открываться через
`NSWorkspace.open` сообразно типу (браузер / файл / приложение).

#### Scenario: Открытие активной ссылки
- **WHEN** открывается `sl://link/<slug>` активной многоразовой ссылки
- **THEN** показывается экран подтверждения с целью, а по подтверждению цель открывается и счётчик переходов растёт

#### Scenario: Неизвестный или истёкший slug
- **WHEN** открывается `sl://link/<slug>`, которого нет или он истёк
- **THEN** показывается состояние «Ссылка недоступна»

### Requirement: Потребление одноразовой ссылки
По переходу одноразовая ссылка SHALL атомарно помечаться `viewed` с проставлением
`consumedAt` и становиться недоступной для повторного перехода. Если включена
настройка «Удалять после перехода», ссылка SHALL удаляться вместо пометки.

#### Scenario: Первое открытие одноразовой
- **WHEN** пользователь подтверждает переход по одноразовой ссылке
- **THEN** цель открывается, ссылка помечается «сгорела» (`viewed`), показывается состояние «Открыто»

#### Scenario: Повторное открытие одноразовой
- **WHEN** пользователь снова открывает уже потреблённую одноразовую ссылку
- **THEN** показывается «Ссылка недоступна», повторный переход не выполняется

#### Scenario: Режим удаления
- **WHEN** включён переключатель «Удалять после перехода» и пользователь переходит по одноразовой
- **THEN** после перехода ссылка удаляется из хранилища

### Requirement: Парольный гейт
Если у ссылки задан пароль, система SHALL запрашивать его перед переходом и открывать
цель только при совпадении с сохранённым хешем.

#### Scenario: Верный пароль
- **WHEN** для защищённой ссылки введён верный пароль
- **THEN** переход выполняется

#### Scenario: Неверный пароль
- **WHEN** введён неверный пароль
- **THEN** цель не открывается и сообщается об ошибке
