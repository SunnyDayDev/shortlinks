# Design — Adopt Pencil Design System

## Context

Дизайн приложения воспроизведён в `design/shortlinks.pen` (Pencil): страница
«Design System» (палитра из ~40 цветовых токенов с темами light/dark, типографика
UI/mono, шкалы `radius-*`/`space-*`, галерея reusable-компонентов — мастера живут в
ней) и семь экранов, собранных из инстансов этих компонентов. Названия и значения
токенов зеркалят код: `Theme`/`Palette` → цветовые переменные, `Typography` →
текстовые стили, `Spacing`/`Radius` → числовые шкалы, atoms/molecules → компоненты
(`Button/Primary`, `Switch`, `StatusPill`, `LinkRow` и т.д.).

Текущие проблемы:
- `design/` не в git — файл существует только локально;
- эталоном в спеках и `CLAUDE.md` числится HTML-макет `_design/…dc.html`,
  который больше не отражает актуальный UI;
- нет правила, обязывающего синхронизировать дизайн-файл при изменениях UI.

Ограничения: `.pen` зашифрован — читается/правится только инструментами Pencil MCP;
дифф в PR нечитаем, ревью дизайна возможно только открытием файла в Pencil.

## Goals / Non-Goals

**Goals:**
- Закрепить `design/shortlinks.pen` как единственный источник правды дизайна.
- Ввести процессное правило синхронизации: UI-изменение ⇒ обновление дизайн-файла.
- Зафиксировать парность токенов/компонентов: код `DesignSystem` ↔ страница
  «Design System» в дизайн-файле (единый нейминг).
- Обновить документацию (`CLAUDE.md`, project-контекст OpenSpec) и спеки.

**Non-Goals:**
- Изменение кода приложения или самого дизайна (это документационно-процессное
  изменение).
- Автоматическая проверка соответствия дизайн-файла коду (CI-линт `.pen` невозможен —
  файл зашифрован; соответствие держится на ревью и конвенции).
- Генерация кода из дизайн-файла или наоборот.

## Decisions

1. **Дизайн-файл в репозитории, а не во внешнем хранилище.**
   `design/shortlinks.pen` коммитится в git рядом с кодом: версия дизайна двигается
   вместе с версией UI в одном PR. Альтернатива — держать файл вне репо (облако) —
   отвергнута: теряется связь «дизайн ↔ коммит» и офлайн-доступ.

2. **Правило синхронизации на уровне PR, а не коммита.**
   Требование: PR с изменением UI (`Sources/ShortlinksApp/**`, кроме чисто
   логических правок) либо содержит обновление `design/shortlinks.pen`, либо в
   описании PR явно указано «визуальных изменений нет». Проверка — ревью по
   договорённости (как и запрет прямых коммитов в `main`); техническое
   принуждение невозможно на бесплатном плане и из-за шифрования файла.

3. **Парность токенов и компонентов, единый нейминг.**
   Новый цвет/шрифт/отступ/компонент добавляется в обе стороны: переменная или
   мастер-компонент на странице «Design System» дизайн-файла + токен/вью в коде
   (`Theme`, `Typography`, `Spacing`, atoms/molecules). Имена согласованы
   (`accent` ↔ `Theme.accent`, `Button/Primary` ↔ `PrimaryButtonStyle`), чтобы
   соответствие проверялось глазами без инструментов.

4. **Экраны в дизайн-файле собираются из инстансов компонентов.**
   Прямая вёрстка «сырыми» фреймами в экранах допустима только для одноразовых
   композиций; повторяющиеся паттерны — только инстансы мастеров. Это правило
   зеркалит существующее требование spec `design-system` («вью переиспользуют
   компоненты, а не inline-вёрстку»).

5. **Эталон визуального паритета — дизайн-файл.**
   В спеке `design-system` требование «Визуальный паритет» перенацеливается с
   `_design/` на `design/shortlinks.pen`. Шрифтовая оговорка: в Pencil используются
   Inter/JetBrains Mono как замена системных SF Pro/SF Mono — паритет оценивается
   по структуре, цветам, размерам и отступам, а не по метрике шрифта.

## Risks / Trade-offs

- [Файл зашифрован — дифф и merge нечитаемы] → правки дизайна вести короткими
  PR; конфликтные ветки не редактируют `.pen` параллельно; при конфликте файл
  берётся целиком из одной ветки и переигрывается.
- [Конвенция без технического принуждения может нарушаться] → правило встроено в
  `CLAUDE.md` и спеки (их читает и ассистент, и человек); чек в описании PR.
- [Дрейф дизайн-файла и кода со временем] → парный нейминг делает расхождения
  заметными; периодическая сверка при ревью UI-PR.
- [Pencil MCP недоступен в среде (CI, чужая машина)] → файл не участвует в сборке,
  его отсутствие в тулчейне ничего не ломает; правки дизайна просто требуют среды
  с Pencil.

## Migration Plan

1. Добавить `design/` в git (включая `.pen`; вспомогательные артефакты Pencil,
   если появятся, — по ситуации в `.gitignore`); удалить `_design/`.
2. Обновить `CLAUDE.md`: раздел «Конвенции» (источник правды дизайна, правило
   синхронизации, парность токенов); убрать упоминания `_design/`.
3. Обновить спеки через delta-файлы этого изменения; `/opsx:sync` + `/opsx:archive`
   выполнить **до открытия PR** — по gitflow правки главных спеков и архивация идут
   тем же PR, что и само изменение (см. [[openspec-archive-before-pr]]).

Откат: удалить правило из `CLAUDE.md`/спеков; файл дизайна и `_design/` остаются в
истории git.
