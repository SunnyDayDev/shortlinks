# Adopt Pencil Design System

## Why

Дизайн приложения перенесён в Pencil-файл `design/shortlinks.pen`: там живут токены
(цвета light/dark, типографика, отступы, радиусы), reusable-компоненты и все экраны.
Сейчас этот файл никак не закреплён в процессе: он не версионируется, конвенции не
требуют сверяться с ним при изменениях UI, а эталоном в спеках всё ещё числится
устаревший HTML-макет `_design/`. Нужен единый источник правды дизайна и правило,
что изменения UI отражаются в нём и соответствуют дизайн-системе.

## What Changes

- Pencil-файл `design/shortlinks.pen` становится **источником правды дизайна**
  (заменяет `_design/Одноразовые ссылки.dc.html` как эталон).
- Старый HTML-макет **`_design/` удаляется** из репозитория (история git сохраняет
  его при необходимости).
- Каталог `design/` версионируется в git; правки файла — только через Pencil MCP
  (файл зашифрован, обычные редакторы/дифф-инструменты неприменимы).
- Рабочий процесс дополняется правилом: **изменение UI сопровождается обновлением
  дизайн-файла** — новый/изменённый экран или компонент сначала (или вместе с PR)
  отражается в `design/shortlinks.pen`.
- UI-изменения обязаны **соответствовать дизайн-системе**: использовать существующие
  токены/компоненты дизайн-файла и их аналоги в коде (`Theme`/`Typography`/`Spacing`/
  `Icons`, atoms/molecules); новые токены и компоненты добавляются парно — в
  дизайн-файл (страница «Design System») и в код.
- Обновляются конвенции: `CLAUDE.md` (раздел о дизайне и процессе), project-контекст
  OpenSpec.

## Capabilities

### New Capabilities

- `design-file`: Pencil-файл `design/shortlinks.pen` как источник правды дизайна —
  структура (страница «Design System» с токенами/компонентами + экраны), соответствие
  токенов и компонентов коду `DesignSystem`, версионирование, редактирование только
  через Pencil MCP.

### Modified Capabilities

- `design-system`: эталон визуального соответствия меняется с макета `_design/` на
  `design/shortlinks.pen`; новые элементы UI добавляются с опорой на компоненты и
  токены, отражённые в дизайн-файле (парность код ↔ дизайн-файл).
- `dev-workflow`: PR, затрагивающий UI приложения, SHALL включать соответствующее
  обновление `design/shortlinks.pen` (или явное указание, что визуальных изменений
  нет).

## Impact

- Git: каталог `design/` добавляется в репозиторий (сейчас untracked); каталог
  `_design/` удаляется.
- Документация: `CLAUDE.md` (конвенции, структура), `openspec/specs/design-system`,
  `openspec/specs/dev-workflow`, project-контекст OpenSpec.
- Код приложения не меняется — изменение процессное/документационное.
- Инструментарий: работа с `.pen` требует Pencil MCP (учтено в памяти ассистента и
  конвенциях).
