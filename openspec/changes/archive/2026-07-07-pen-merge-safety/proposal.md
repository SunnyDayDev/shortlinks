# Document .pen Merge Safety

## Why

Ранее принятое изменение `adopt-pencil-design-system` зафиксировало, что `design/shortlinks.pen`
«зашифрован» и не поддаётся `Read`/`grep`/дифф-инструментам. Это фактически неверно: файл —
**обычный валидный JSON** (`{version, themes, variables, children[], fileToken}`), человекочитаемый
и диффабельный. Значит его **можно мержить** — и полезно зафиксировать, при каких условиях
слияние безопасно, а когда требуется ручное разрешение. Это снимает страх перед параллельными
ветками, меняющими дизайн.

## What Changes

- Исправить неверное утверждение «файл зашифрован»: `.pen` — plain JSON, читается и диффается;
  через Pencil MCP ведётся **редактирование** (чтобы сохранять структурные инварианты — id,
  `ref`, схему), а не потому, что файл нечитаем.
- Зафиксировать **модель безопасного слияния** `.pen`. Слияние безопасно (автомерж-объединение
  обеих веток), когда выполнены **все** условия:
  1. правки затрагивают **разные top-level `children`** (разные фреймы экранов/областей);
     добавление нового top-level ребёнка тоже считается непересекающимся;
  2. все ссылки `$variableName` присутствуют в `variables` после слияния;
  3. все `id` узлов остаются **глобально уникальными** после слияния;
  4. **ссылочная целостность**: каждый `ref` разрешается в существующий reusable-компонент,
     каждый ключ `descendants` — в реальный путь потомка;
  5. правки `variables`/`themes` **аддитивны и не конфликтуют** (один ключ не задан разными
     значениями), `version` совпадает.
- Отметить практический нюанс: **все мастера-компоненты и токены живут в одном top-level
  ребёнке «Design System»**, поэтому любые две ветки, обе меняющие дизайн-систему (компоненты
  или токены), пересекаются по этому ребёнку → условие 1 не выполнено → ручной мерж.
- В остальных случаях (один и тот же ребёнок правлен с обеих сторон; конфликт
  переменной/темы/`id`; висячий `ref`; несовпадение `version`) — ручное разрешение конфликта в
  JSON или выбор одного из вариантов файла целиком.
- Обновить документацию: `CLAUDE.md` (убрать «зашифрован», добавить модель мержа), спеку
  `design-file`; поправить ошибочную ремарку «файл зашифрован» в требовании `dev-workflow`.

## Capabilities

### New Capabilities

_Нет._

### Modified Capabilities

- `design-file`: убрать утверждение о шифровании (файл — plain JSON, читается/диффается;
  Pencil MCP — для сохранения инвариантов при редактировании), добавить требование о модели
  безопасного слияния `.pen` (условия автомержа + ручной фолбэк).
- `dev-workflow`: исправить в требовании «Синхронизация дизайн-файла при изменениях UI»
  ошибочную причину «файл зашифрован» (остаётся действительная — branch protection недоступна).

## Impact

- Документация: `CLAUDE.md`, `openspec/specs/design-file`, `openspec/specs/dev-workflow`.
- Код приложения не меняется. Опционально — небольшой валидатор-скрипт, проверяющий инварианты
  (`id`-уникальность, разрешимость `$var` и `ref`) как основу для «безопасно ли смержено».
- Снимает ограничение восприятия: параллельные правки разных экранов теперь можно сливать без
  страха, по чётким правилам.
