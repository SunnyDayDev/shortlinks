## Context

Пользовательский текст и имена SF Symbols сейчас захардкожены литералами по месту в трёх
таргетах: ~85 строк во вью (`Sources/ShortlinksApp/Views/*`, `MainView.swift`, тосты
`AppModel`), презентационные строки ядра (`Format.swift`, `Scheme.swift`), тексты CLI
(`abstract`/`help`/вывод в `ShortlinksCLI.swift`) и ~16 уникальных имён SF Symbols. Всё
на русском. Локализационной инфраструктуры нет (`.xcstrings`/`.strings`/`.lproj`
отсутствуют). Русское склонение по числу собрано вручную в `Format.plural` (3 формы).

Ограничения и точки опоры:
- Дизайн-система уже задаёт принцип «во вью нет магических литералов» (цвета/шрифты/отступы
  → токены-enum `Theme`/`Typography`/`Spacing`). Строки и иконки — единственные оставшиеся
  сырые литералы. Новые реестры должны повторять эту конвенцию (типизированные enum).
- Сборка на **XcodeGen + xcodebuild** (не SPM): у статической библиотеки нет `Bundle.module`.
- `ShortlinksCore` — `library.static`, переиспользуется и приложением, и CLI.
- CLI **вкладывается** в бандл приложения (`Contents/Helpers/shortlinks`) и из терминала
  доступен через симлинк; отдельной установки нет. Это устойчивый инвариант проекта.
- Цель — подготовка к переводу (заявлено пользователем). Сам перевод на конкретный второй
  язык — отдельная будущая итерация.
- Решение пользователя по развилкам: (1) типизированный `Strings` enum; (2) охват — всё,
  включая CLI.

## Goals / Non-Goals

**Goals:**
- Единый типизированный реестр `Strings` поверх String Catalog; во вью/CLI/ядре нет сырых
  пользовательских строковых литералов.
- Единый реестр `Icons` имён SF Symbols; во вью нет сырых имён символов.
- Корректные русские склонения через правила каталога (а не ручную сборку).
- Встроенный CLI резолвит локализацию из ресурсов приложения, следуя системным предпочтениям
  языка и уважая `LANG`/`LC_*` и флаг `--lang`; standalone-CLI не падает.
- Рефактор без изменения видимого текста и поведения (русский паритет), существующие тесты
  зелёные.

**Non-Goals:**
- Перевод на конкретный второй язык (en и т.п.) — только инфраструктура и язык-источник ru.
- Переключатель языка в UI — GUI следует системной локали (CLI дополнительно уважает
  `LANG`/`LC_*`/`--lang`, см. решение 4a).
- Локализация технических литералов (схемы `sl://`/`https://`, ключи, значения
  фильтров/TTL, коды типа `web/doc/app/txt` в `TargetIcon`).
- Превращение `ShortlinksCore` в динамический framework.

## Decisions

### 1. String Catalog (`Localizable.xcstrings`), не legacy `.strings`/`.stringsdict`
Цель развёртывания — macOS 14 (Xcode 15+), доступен `String(localized:)` и String
Catalog. Каталог нативно поддерживает plural-вариации (CLDR), заменяя `.stringsdict`, и
является штатной поверхностью перевода в современном тулинге Apple.
*Альтернатива:* пара `Localizable.strings` + `Localizable.stringsdict` — устаревший путь,
ручные `.stringsdict`-правила, нет редактора каталога. Отклонено.

### 2. Типизированный реестр `Strings` (public) в ShortlinksCore
Единый `public enum Strings` с вложенными namespace по экранам/доменам
(`Strings.Create.*`, `Strings.Settings.*`, `Strings.Redirect.*`, `Strings.Sidebar.*`,
`Strings.Detail.*`, `Strings.Status.*`, `Strings.CLI.*`, `Strings.Toast.*`,
`Strings.Common.*`). Каждый аксессор — `String(localized: "<key>", defaultValue:
"<рус>", bundle: .shortlinks, comment: …)`.

Почему в Core: реестр нужен всем трём таргетам (вью, ядро, CLI), а Core — общий слой
(`Format.swift` уже держит презентационные строки в ядре). Это повторяет конвенцию
дизайн-системы: один типизированный источник, как `Theme`/`Typography`, заполняемый
вручную.
*Альтернатива A:* инлайн-литералы как ключи каталога (`Text("Новая ссылка")`,
авто-извлечение Xcode) — идиоматично для SwiftUI и даёт авто-синхронизацию каталога, но
оставляет литералы во вью и не даёт типобезопасного единого реестра. Отклонено по выбору
пользователя.
*Альтернатива B:* три отдельных enum по таргетам — даёт авто-извлечение для app-таргета,
но дробит реестр и не соответствует модели «единый `Strings`». Отклонено.

### 3. Русский — язык-источник в `defaultValue`; каталог — поверхность перевода
`String(localized:defaultValue:)` возвращает `defaultValue`, когда перевод/каталог
отсутствует. Это:
- гарантирует посимвольный русский паритет без полного заполнения каталога;
- делает данную итерацию **выносом строк (extraction) + инфраструктурой**, а не переводом;
- держит канонический русский текст в одном месте — в файле реестра `Strings`
  (что для выбранного «единого типизированного enum» и есть тот самый ресурс-источник).

Каталог регистрируется с dev-регионом `ru`; non-plural ключи опираются на `defaultValue`,
а конкретные переводы добавляются по ключам реестра при заведении языка (будущая итерация).
Plural-ключи заводятся в каталоге явно (см. п.5).

### 4. Bundle-локатор `Bundle.shortlinks` для встроенного CLI; Core остаётся static lib
Один общий каталог кладётся в ресурсы **app-таргета** (всегда есть бандл). Резолвинг:
- **Приложение**: `Bundle.main` — это `.app`, каталог в `Contents/Resources`.
- **Встроенный CLI**: исполняемый файл в `Contents/Helpers/shortlinks`; ресурсы берутся из
  соседнего `Contents/Resources` (вычисляется от `Bundle.main.bundleURL` → `../Resources`,
  `Bundle(url:)`). Симлинк из `~/.local/bin` резолвится в реальный путь внутри `.app`, путь
  сохраняется.
- **Фолбэк**: если каталог не найден (standalone-сборка CLI) — `.main`; строки отдаются из
  `defaultValue`.

Почему так, а не framework: динамический framework дал бы `Bundle(for:)` и авто-извлечение
строк Core, но требует встраивания фреймворка в **tool-таргет** (`@rpath`,
`Contents/Frameworks`, подпись) — заметная сложность ради самоподписанного хобби-приложения.
Локатор через известную раскладку бандла проще и использует уже зафиксированный инвариант
«CLI вложен в `.app`».
*Trade-off:* call-site’ы `String(localized:)` живут в Core (и в CLI), поэтому
Xcode-авто-извлечение в app-каталог по ним не срабатывает — каталог ведётся вручную/через
`defaultValue` (см. Risks).

### 4a. Выбор языка CLI: системные предпочтения + `LANG`/`LC_*`/`--lang`
Foundation выбирает `.lproj` по `AppleLanguages` (системные предпочтения) и НЕ смотрит на
POSIX-переменные `LANG`/`LC_*`. Чтобы CLI был предсказуем и для системы, и для скриптинга,
вводится единый слой выбора предпочитаемых языков (в ShortlinksCore), приоритет сверху вниз:
1. флаг `--lang <code>` (глобальная опция CLI);
2. `LC_ALL`, затем `LC_MESSAGES`, затем `LANG` (POSIX-приоритет) — язык извлекается из
   значения вида `ru_RU.UTF-8` (часть до `_`/`.`); `C`/`POSIX` трактуются как «без локали»;
3. системные `AppleLanguages` (поведение по умолчанию, как у GUI);
4. фолбэк — язык-источник `ru` (`defaultValue`).
Выбранный язык сопоставляется с доступными локализациями каталога
(`Bundle.preferredLocalizations(from:forPreferences:)`), строки грузятся из конкретного
`<lang>.lproj` — предсказуемо и без зависимости от кеша `preferredLocalizations`. GUI override
не задаёт (слой отдаёт системные предпочтения). Тот же слой отдаёт согласованную `Locale` для
форматтеров (см. решение 6), чтобы язык текста и формат дат не расходились.
*Почему так:* база — системная локаль (консистентно с приложением), а `LANG`/`--lang` —
привычное для CLI переопределение под скрипты/CI.

### 5. Склонения — plural-вариации каталога; ручной `Format.plural` ретайрится
Числовые формы («N переход(а/ов)», «N час(а/ов)», «N день/дня/дней», «Удалить N
ссылку/ссылки/ссылок») переводятся на plural-ключи каталога с аргументом `%lld` и
категориями CLDR (для ru: one/few/many/other). Это единственные ключи, которые **заводятся
в каталоге явно** уже в этой итерации (их немного), т.к. русские формы нельзя выразить одним
строковым `defaultValue`. `Format.plural`/`opensText` переключаются на каталог; ручная
функция склонения удаляется (или сводится к тонкой обёртке над `String(localized:)`).

### 6. Локаль форматтеров — согласована с выбранным языком, не захардкоженная `ru_RU`
`Format.expiresText` сейчас жёстко берёт `Locale(identifier: "ru_RU")` в `DateFormatter`.
Форматтеры переводятся на `Locale`, который отдаёт слой выбора локали (решение 4a): в GUI это
эффективно системная локаль, в CLI — с учётом `LANG`/`--lang`. Так язык текста и формат
дат/времени не расходятся. Русский паритет сохраняется (при ru-локали вывод тот же).

### 7. Реестр `Icons` — в слое дизайн-системы приложения
`enum Icons` (семантические сгруппированные константы имён SF Symbols:
`Icons.Action.add`, `Icons.Nav.back`, `Icons.Filter.once`, `Icons.Status.expired` и т.п.)
в `Sources/ShortlinksApp/DesignSystem/`. Иконки — чисто UI-аспект (в CLI их нет), поэтому,
в отличие от строк, реестр живёт в приложении, а не в Core. Сигнатуры атомов
`IconTile`/`TargetIcon` (`systemName: String`) сохраняются; на call-site’ах вместо литералов
передаётся `Icons.*`. Кастомных растровых картинок нет — «библиотека иконок» = реестр имён
символов; `AppIcon.appiconset` не затрагивается.

### 8. `Text`/`Label` получают уже-резолвленный `String`, не `LocalizedStringKey`
`Strings.*` возвращает готовый `String` (после `String(localized:)`). `Text(strVar)`/
`Button(strVar)` используют не-локализующую перегрузку `StringProtocol` и показывают текст
как есть — двойной локализации не происходит. Литералы в `Text("…")` (которые SwiftUI
трактует как `LocalizedStringKey`) не используются.

### 9. Сборка: `project.yml`
В app-таргет добавляется ресурс `Localizable.xcstrings` (источники app-таргета) и
`CFBundleDevelopmentRegion: ru` + `CFBundleLocalizations` (стартово `[ru]`, расширяется при
переводе). После правки — `xcodegen generate`. Зависимостей не добавляется. Конвенции в
`CLAUDE.md` дополняются (строки → `Strings`, иконки → `Icons`).

## Risks / Trade-offs

- **Нет Xcode-авто-извлечения в каталог** (call-site’ы в Core/CLI) → каталог ведётся вручную;
  *Mitigation:* `defaultValue` гарантирует корректный рантайм-вывод без записей в каталоге;
  реестр `Strings` — единый список ключей для переводчика; в задачи входит шаг-инструкция
  «как завести язык» и заполнение только plural-ключей сейчас.
- **Standalone-сборка CLI без `.app`** теряет переводы → *Mitigation:* фолбэк локатора на
  `.main`/`defaultValue`; для ru (язык-источник) вывод идентичен. Реальный дистрибутив — это
  всегда встроенный в `.app` CLI.
- **Foundation не смотрит `LANG`/`LC_*`** для выбора `.lproj` → *Mitigation:* слой выбора
  локали (решение 4a) сам маппит `LANG`/`LC_*`/`--lang` в язык и грузит нужный `<lang>.lproj`,
  не полагаясь на `AppleLanguages`-кеш.
- **`LANG=C`/`POSIX` или нераспознанный код** → *Mitigation:* трактуются как «без локали» →
  фолбэк на язык-источник `ru`; выполнение не прерывается.
- **`--lang` и тайминг `--help`**: тексты `--help` берутся из `static let configuration`,
  вычисляемой парсером до `run()` → *Mitigation:* env-сигналы (`LANG`/`LC_*`) и системные
  предпочтения применяются в самом начале `main` и влияют на `--help`; флаг `--lang`
  гарантированно влияет на вывод команд, но не обязательно на текст `--help` — приемлемый край.
- **Пропуск строки/иконки при миграции / регресс текста** → *Mitigation:* grep-проверки
  (нет литералов в `Text(...)`/`systemName:`/`systemImage:`/`abstract:`/`help:` по
  каталогам), сверка русского текста, прогон `ShortlinksCoreTests`, ручная визуальная
  сверка экранов с `_design/`.
- **Неверная категория plural для ru** → *Mitigation:* юнит-тесты на `opensText`/счётчики
  для n ∈ {1,2,5,11,21,…} сверяют формы; правила каталога повторяют текущую логику
  `Format.plural`.
- **Коды `web/doc/app/txt` в `TargetIcon`** — пограничный пользовательский текст; решено
  считать универсальными техаббревиатурами и **не** локализовать (зафиксировано в
  Non-Goals; пересмотреть при реальном переводе, если потребуется).

## Migration Plan

Чистый рефактор источника строк/иконок, без изменения данных/схемы и наблюдаемого
поведения. Поэтапно (см. `tasks.md`):
1. Инфраструктура: `Bundle.shortlinks`-локатор и слой выбора локали (система +
   `LANG`/`LC_*`/`--lang`), скелет `Strings`, `Localizable.xcstrings` (dev-регион ru,
   plural-ключи), реестр `Icons`; правка `project.yml` + `xcodegen generate`.
2. Миграция Core: `Format.swift` (склонения → каталог, лейблы → `Strings`, локаль форматтеров
   → из слоя выбора локали), `Scheme.swift` (лейблы → `Strings`).
3. Миграция приложения: все `Views/*`, `MainView.swift`, тосты `AppModel` → `Strings.*`;
   имена символов → `Icons.*`.
4. Миграция CLI: `abstract`/`help`/`print`/`ValidationError` → `Strings.CLI.*`; глобальный
   `--lang` и чтение `LANG`/`LC_*` (применить override локали в точке входа).
5. Верификация: сборка app и CLI, `ShortlinksCoreTests`, grep-проверки отсутствия литералов,
   визуальная сверка.

**Rollback:** изменения изолированы в ветке `feat/extract-strings-and-icons`; откат — revert
ветки. Рисков для пользовательских данных нет.
