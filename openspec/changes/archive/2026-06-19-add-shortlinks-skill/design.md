## Context

`shortlinks` CLI (`Sources/shortlinks-cli/ShortlinksCLI.swift`) предоставляет команды
`add/list/rm/resolve/open` поверх общего хранилища `links.json`. CLI вложен в
`Shortlinks.app/Contents/Helpers/shortlinks` и доступен из терминала через симлинк
`~/.local/bin/shortlinks` (`CLIInstaller`).

Нужен переиспользуемый Claude-навык, обучающий агентов вызывать этот CLI. По решению
пользователя навык оформляется как **устанавливаемый Claude-плагин** и покрывает
**полный набор команд**. В репозитории уже есть навыки в `.claude/skills/` (openspec) —
но это локальные навыки проекта, не предназначенные для распространения; новый артефакт
должен быть отдельным переносимым плагином.

## Goals / Non-Goals

**Goals:**
- Самодостаточный навык, по которому агент без доп. контекста создаёт/находит/резолвит/
  открывает ссылки и корректно парсит вывод.
- Оформление как плагина с манифестом, пригодного для установки в другие агенты.
- Точное соответствие реальному поведению CLI (опции, формат вывода, ошибки, путь
  `Contents/Helpers`).

**Non-Goals:**
- Изменение кода CLI/приложения или добавление новых команд.
- Публикация в публичный маркетплейс/реестр (только структура + инструкция установки).
- MCP-сервер или собственные tool-определения — навык опирается на вызовы CLI через bash.

## Decisions

### Решение: структура плагина в репозитории

Каталог плагина — `plugins/shortlinks/` в корне репозитория:

```
plugins/shortlinks/
  .claude-plugin/
    plugin.json          # name, description, version, author
  skills/
    shortlinks/
      SKILL.md           # фронтматтер name/description + тело навыка
```

Авто-дискавери Claude-плагина подхватывает каталог `skills/`. Манифест — минимальный,
но с `description` для каталога/маркетплейса.

**Альтернативы:**
- Просто `skills/shortlinks/SKILL.md` без манифеста (вариант «в репо + копирование») —
  отвергнут: пользователь выбрал формат плагина.
- Положить рядом с openspec-навыками в `.claude/skills/` — это локальные навыки
  проекта, не переносимый плагин; смешивать не стоит.

### Решение: содержание SKILL.md

Тело навыка структурируется по реальному поведению CLI:
- **Что это** — `sl://link/<slug>`, локальное хранилище, одноразовые vs многоразовые.
- **Доступность CLI** — `command -v shortlinks`; fallback на
  `~/Applications/Shortlinks.app/Contents/Helpers/shortlinks` или
  `/Applications/Shortlinks.app/Contents/Helpers/shortlinks`; как установить из приложения.
- **Команды** — таблица/блоки с примерами:
  - `add <target> [--slug] [--once|--reuse] [--ttl 1h|24h|7d|never] [--password] [-g/--tag …]` → печатает `sl://link/<slug>`.
  - `list [--filter all|active|once|expired] [--tag]` → строки `<url> [<kind> · <status>] → <target>`.
  - `rm <slug>`, `resolve <slug>` (печатает цель), `open <slug> [--password] [--delete-on-consume]`.
- **Парсинг и семантика** — slug из `sl://link/<slug>`; `open` потребляет одноразовую,
  `resolve` — нет.
- **Ошибки** — «не найдена», «недоступна (истекла/потреблена)», «требуется --password»
  (ненулевой код возврата).
- **Когда что** — `resolve` для чтения цели без потребления, `open` для перехода.

### Решение: инструкция распространения

В `README.md` добавляется раздел «Использование навыка в других агентах» с командой
установки плагина (из локального пути/Git-репозитория) — конкретный синтаксис
сверяется с актуальной документацией Claude Code на этапе apply.

## Risks / Trade-offs

- [Формат `plugin.json`/механизм установки плагинов может отличаться от ожидаемого] →
  на этапе apply сверить структуру и команду установки с актуальной документацией
  Claude Code (через claude-code-guide); правка локализована в манифесте и README.
- [Навык рассинхронизируется с CLI при будущих изменениях команд] → навык явно ссылается
  на capability `cli-interface` как источник истины; при изменении CLI обновлять навык.
- [Путь к вложенному CLI зависит от ОС-раскладки бандла] → фиксируем
  `Contents/Helpers/shortlinks` (после fix-cli-bundle-path-collision) и проверяем
  `command -v` в первую очередь.

## Migration Plan

1. Создать `plugins/shortlinks/.claude-plugin/plugin.json` и `skills/shortlinks/SKILL.md`.
2. Сверить формат плагина/скилла и команду установки с актуальной документацией.
3. Добавить раздел установки в `README.md`.
4. Проверить навык на соответствие реальному CLI (примеры команд запускаются, вывод
   совпадает); по возможности установить/активировать плагин и убедиться, что навык
   виден.
5. Откат: удалить каталог плагина и раздел README (обратимо одним коммитом).
