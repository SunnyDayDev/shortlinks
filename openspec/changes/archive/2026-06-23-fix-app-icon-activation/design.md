## Context

Change `deeplink-silent-open` сделал приложение фоновым агентом (`LSUIElement`) и
заменил сцену SwiftUI `Window` на ленивое AppKit-окно (`AppDelegate.showMainWindow`),
чтобы тихий `sl://` не мигал окном. Окно создаётся только по требованию:
`surfaceForInteraction` (UI для перехода) и пункты меню-бара. Никто не показывает окно
при «обычном» запуске или reopen, поэтому клик по иконке ничего не открывает.

Ограничение: `application(_:open:)` для URL-запуска вызывается **после**
`applicationDidFinishLaunching`. Значит в момент `didFinishLaunching` ещё неизвестно,
запущено ли приложение ради `sl://` или просто кликом.

## Goals / Non-Goals

**Goals:**
- Обычный запуск (клик по иконке, Spotlight, Launchpad) показывает главное окно.
- Reopen уже запущенного агента показывает/поднимает окно.
- Тихий `sl://` не регрессирует: запуск ради URL окно не показывает.

**Non-Goals:**
- Возврат сцены SwiftUI `Window` / отказ от агент-режима.
- Изменение логики самого перехода по ссылке.

## Decisions

### 1. Отличаем launch-with-URL от обычного запуска отложенной проверкой
В `applicationDidFinishLaunching` привязываем замыкания и планируем на следующий тик
рунлупа (`DispatchQueue.main.async`) проверку флага `didOpenURLAtLaunch`. URL-событие
(`application(_:open:)`) приходит во время запуска до простоя рунлупа и успевает
выставить флаг. Если к моменту async-блока флаг не выставлен — это обычный запуск,
показываем окно через `surfaceForInteraction(forRedirect: false)`.

- **Почему так:** надёжно разделяет «запущен ради ссылки» и «запущен кликом» без
  приватных API. `application(_:open:)` гарантированно опережает отложенный блок.
- **Альтернативы:**
  - *Показывать окно сразу в `didFinishLaunching`.* Сломает тихий `sl://`: при
    URL-запуске окно мигнёт до прихода `open`.
  - *`NSAppleEventManager`/проверка `kAEOpenDocuments` вручную.* Сложнее и хрупче
    отложенной проверки флага.

### 2. Reopen — через `applicationShouldHandleReopen(_:hasVisibleWindows:)`
Клик по иконке уже запущенного агента доставляется как reopen. В обработчике зовём
`surfaceForInteraction(forRedirect: false)` и возвращаем `true`.

- **Почему так:** штатный хук AppKit для «иконку нажали повторно». `forRedirect: false`
  — окно открыто пользователем, авто-возврата в фон не нужно.

## Risks / Trade-offs

- **[Гонка: async-блок выполнится раньше `application(_:open:)`]** → на практике
  URL-Apple-event обрабатывается в той же фазе запуска до возврата в рунлуп, поэтому
  `async` (следующий тик) приходит позже. Если когда-нибудь нарушится — худший случай
  кратковременное окно при `sl://`, не потеря функции.
- **[Двойной показ окна]** → `showMainWindow` идемпотентен (окно создаётся один раз,
  `makeKeyAndOrderFront` повторяемо); повторные вызовы безопасны.
