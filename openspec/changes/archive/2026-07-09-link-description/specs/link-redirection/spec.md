## MODIFIED Requirements

### Requirement: Поток подтверждения перехода
При открытии `sl://link/<slug>` система SHALL найти ссылку и показать оверлей
перехода с тремя состояниями: подтверждение (`ready`) для активной ссылки,
заблокировано (`blocked`) для просмотренной/истёкшей, выполнено (`consumed`) после
перехода по одноразовой. По подтверждению цель SHALL открываться через
`NSWorkspace.open` сообразно типу (браузер / файл / приложение). На экране
подтверждения цель (`target`) SHALL показываться только для **незащищённой** ссылки;
для защищённой паролем ссылки цель SHALL быть скрыта (см. «Парольный гейт») — экран
показывает короткий адрес `sl://link/<slug>` и запрос пароля, не раскрывая цель. Если у
ссылки задано описание (`note`), экран подтверждения SHALL показывать это описание —
в том числе для защищённой ссылки, так как описание является авторской подписью, а не
самой целью, и не маскируется.

#### Scenario: Открытие активной незащищённой ссылки
- **WHEN** открывается `sl://link/<slug>` активной многоразовой ссылки без пароля (в режиме подтверждения)
- **THEN** показывается экран подтверждения с целью, а по подтверждению цель открывается и счётчик переходов растёт

#### Scenario: Открытие защищённой ссылки не раскрывает цель
- **WHEN** открывается `sl://link/<slug>` защищённой паролем ссылки
- **THEN** экран подтверждения показывает адрес `sl://link/<slug>` и поле ввода пароля, но НЕ показывает цель перехода

#### Scenario: Описание на экране подтверждения
- **WHEN** открывается `sl://link/<slug>` ссылки с заданным описанием (в режиме подтверждения или для защищённой ссылки)
- **THEN** на экране подтверждения показывается описание ссылки

#### Scenario: Неизвестный или истёкший slug
- **WHEN** открывается `sl://link/<slug>`, которого нет или он истёк
- **THEN** показывается состояние «Ссылка недоступна»
