## Context

Ссылка (`Link`, ShortlinksCore) уже несёт метаданные помимо цели: `tags`, `kind`,
`passwordHash`, `disabledAt`. Формат хранения — единый `links.json`, каждая запись —
`Codable`-структура `Link`; чтение/запись координируются `NSFileCoordinator`, слияние
конфликтов iCloud идёт по `id` (`ConflictMerge`). В интерфейсе ссылку показывают три
поверхности: список (`LinkListView`/`LinkRow`), карточка деталей (`LinkDetailView`) и
оверлей перехода (`RedirectOverlay`). Создание — форма `CreateSheet` поверх
`AppModel.CreateForm` и `Link.make`, а также CLI-команда `add`. Цель защищённой ссылки
маскируется на уровне интерфейса (см. change `hide-protected-link-target`).

Нужно дать пользователю необязательную человекочитаемую подпись «куда ведёт / что
откроется». Изменение аддитивно расширяет модель и три поверхности отображения.

## Goals / Non-Goals

**Goals:**
- Необязательное поле описания (`note`) у `Link`, задаваемое при создании (форма и CLI).
- Показ описания в карточке деталей, строке списка и оверлее подтверждения перехода.
- Участие описания в поиске.
- Обратная совместимость с существующими `links.json` (без миграции).
- Обновление дизайн-файла `design/shortlinks.pen` парно с кодом.

**Non-Goals:**
- Редактирование описания у уже созданной ссылки — вне объёма (как и правка `target`,
  тегов, пароля). При необходимости — отдельное изменение.
- Форматирование/Markdown в описании — обычный однострочно-многострочный текст.
- Ограничение длины на уровне модели/хранилища (UI может усечь при показе).
- Изменение логики слияния конфликтов.

## Decisions

### 1. Поле `note: String?` в `Link`
Добавляем `public var note: String?` (JSON-ключ `note`), необязательное. Параметр
`Link.make(note: String? = nil)` нормализует значение: `trimmingCharacters(in:
.whitespacesAndNewlines)`, пустое → `nil`. Инициализатор `Link.init` получает
`note: String? = nil` последним параметром (после `disabledAt` или рядом с прочими
метаданными — порядок не влияет на JSON).

*Почему `note`, а не `description`:* короче, не конфликтует с `CustomStringConvertible`
и привычной семантикой «пометка». Пользовательская подпись в UI — «Описание».
*Альтернатива:* хранить описание вне `Link` (отдельный словарь) — отклонено: описание
концептуально принадлежит ссылке и должно сливаться/переноситься вместе с ней.

### 2. Обратная совместимость через опциональность
`note` — опциональное свойство, поэтому синтезированный `Codable` декодирует старые
записи без ключа как `note == nil`, а не задаёт ошибку. Миграция файла не нужна; новые
записи просто получают дополнительный ключ (когда описание задано). Пустое описание не
сериализуется как `""` — нормализуется в `nil`, чтобы не плодить пустые ключи и не
считать «пустую строку» описанием.

### 3. `ConflictMerge` не меняется
Слияние идёт по `id` целой записью (`resolve` выбирает победившую версию `Link`
целиком), поэтому `note` едет вместе с выбранной записью — отдельная логика для поля не
нужна. Так как в этом изменении описание неизменяемо после создания, обе конфликтующие
версии одной ссылки несут одинаковый `note`; расхождения быть не может. Тест на
сохранность `note` при merge добавляем как страховку.

### 4. Не маскируется для защищённых ссылок
Маскирование (`hide-protected-link-target`) скрывает **цель** защищённой ссылки, потому
что это то, что открывается. Описание — авторская подпись, её пишет тот же
пользователь, что ставит пароль; она не является целью и не раскрывает её
автоматически. Поэтому описание показывается обычным текстом на всех поверхностях, в том
числе для защищённой ссылки и на экране подтверждения. Это прямо служит цели изменения —
«понять, что откроется», — не ослабляя защиту самой цели.

### 5. Поиск: подстрочное совпадение
В `AppModel.filteredLinks` добавляем к предикату поиска
`(link.note?.lowercased().contains(q) ?? false)` — регистронезависимое подстрочное
совпадение, единообразно со slug/target/tags. Счётчики в сайдбаре не зависят от поиска и
не меняются.

### 6. Поверхности отображения
- **Карточка деталей** (`LinkDetailView.infoCard`): строка описания через существующий
  `InfoRow` (или многострочный вариант при длинном тексте), показывается только когда
  `note` задано. Размещается первой строкой карточки — перед «Перенаправляет на»
  (согласовано в дизайн-файле).
- **Строка списка** (`LinkRow`): когда `note` задано, вторая строка показывает описание
  **вместо** цели/маски (`text-primary`, `lineLimit(1)`); когда не задано — цель, как
  прежде. Без дополнительной иконки. Порядок: slug → описание|цель → subtitle → теги.
- **Оверлей перехода** (`RedirectOverlay`): описание в блоке подтверждения, когда задано.
- **Форма создания** (`CreateSheet`): многострочное необязательное поле «Описание»
  (`TextField(axis: .vertical)`), после «Короткий адрес», перед «Тип/Срок», через
  существующий `LabeledField`/`fieldBox()`.

### 7. CLI
- `add`: опция `@Option --note` (без короткого алиаса, чтобы не конфликтовать с `-g`
  тегов), пробрасывается в `Link.make(note:)`.
- `list`: когда `note` задано, дописываем его к строке вывода (например, второй строкой
  с отступом или в скобках) — формат читаемый, существующие поля не меняются.
- `resolve`/`open` не трогаем: они машинно-ориентированы (печатают/открывают цель).

### 8. Локализация
Новые пользовательские строки — только через реестр `Strings` (ShortlinksCore) с русским
`defaultValue` и записью в `Localizable.xcstrings` (источник — русский), без хардкода в
вью/CLI. Ориентировочные ключи: `create.noteLabel`, `create.notePlaceholder`,
`detail.note`, `cli.add.note`. Формат вывода описания в CLI-`list` — тоже через `Strings`,
если требуется подпись.

### 9. Дизайн-файл
Правки в `design/shortlinks.pen` внесены **через Pencil MCP** (сохранение инвариантов) на
всех четырёх поверхностях: поле «Описание» на экране создания (после «Короткий адрес»),
строка «Описание» первой в карточке деталей, описание вместо цели в строке списка
(`LinkRow`), описание в оверлее перехода. Собрано из существующих токенов/компонентов
(`LabeledField`, `InfoRow`, `LinkRow`) — новых токенов/компонентов не вводим. Проверено
`python3 design/validate_pen.py` (инварианты целы).

## Risks / Trade-offs

- [Описание защищённой ссылки может косвенно намекать на цель] → Это осознанный выбор
  пользователя: подпись пишет он сам. Маскируется именно цель; описание — добровольная
  метка. Документируем поведение в спеке.
- [Длинное описание в строке списка] → описание показывается **вместо** цели (не добавляет
  строку) и усекается `lineLimit(1)`; строка не растёт по высоте.
- [Рассинхрон дизайн-файла и кода] → Требование gitflow: UI-PR включает обновление
  `.pen`; правка через Pencil MCP + `validate_pen.py`.
- [Расхождение форматов вывода CLI] → `list` дополняется аддитивно, порядок и наличие
  существующих полей сохраняются, чтобы не сломать возможный парсинг вывода.

## Migration Plan

Миграция не требуется: `note` — опциональное поле, старые `links.json` читаются как есть.
Откат — обратный (поле перестаёт писаться); ранее записанные `note` игнорируются старой
версией без ошибок декодирования, так как неизвестные/лишние ключи не ломают декодирование
известных полей, а отсутствие `note` в старом коде — норма.
