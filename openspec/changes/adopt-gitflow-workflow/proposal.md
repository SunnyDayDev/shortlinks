## Why

Сейчас процесс разработки нигде не зафиксирован, и часть работы попадала прямо в
`main`. Нужно явно закрепить правило: любая работа ведётся в отдельной ветке и
вливается в `main` только через Pull Request — чтобы история была чистой, изменения
проходили ревью, а `main` всегда оставался рабочей и защищённой веткой.

## What Changes

- Вводится единый процесс разработки на основе gitflow: `main` — стабильная ветка,
  весь новый функционал и правки делаются в отдельных ветках.
- Прямые коммиты в `main` запрещены; интеграция изменений — только через PR.
- Закрепляется конвенция именования веток (`feat/…`, `fix/…`, `chore/…`, `docs/…`).
- PR должен пройти проверки (сборка/спеки) и быть смержен в `main` (merge-commit),
  после чего ветка удаляется.

## Capabilities

### New Capabilities
- `dev-workflow`: правила ветвления, запрет прямых коммитов в `main`, требования к
  PR и слиянию (gitflow).

## Impact

- Процесс/документация репозитория (не код приложения): описывает, как вносятся
  изменения в shortlinks.
- Затрагивает повседневный git-флоу автора и ассистента; согласуется с уже
  сохранённым предпочтением «gitflow, мерж через PR в main».
- Опционально: настройка branch protection для `main` в GitHub.
