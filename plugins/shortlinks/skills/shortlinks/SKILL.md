# Shortlinks CLI

`shortlinks` — локальный сервис коротких ссылок для macOS. Короткий адрес — кастомная
схема `sl://link/<slug>`; цель перехода — `https://`, `file://`, любой app-scheme или
путь. Хранилище локальное (общий `links.json`), сетевого сервера нет.

Ссылки бывают:
- **многоразовые** (`reuse`, по умолчанию) — работают сколько угодно раз;
- **одноразовые** (`once`) — «сгорают» после первого перехода (`open`).

Срок жизни (`--ttl`): `1h`, `24h`, `7d`, `never` (по умолчанию `never`).

## Доступность CLI

1. Сначала проверь, что команда в `PATH`:
   ```bash
   command -v shortlinks
   ```
   Если найдена — вызывай просто `shortlinks <команда>`.
2. Если не найдена, используй вложенный в приложение бинарь (подставь как полный путь):
   ```bash
   ~/Applications/Shortlinks.app/Contents/Helpers/shortlinks --help
   # или, если приложение в системной папке:
   /Applications/Shortlinks.app/Contents/Helpers/shortlinks --help
   ```
3. Чтобы команда `shortlinks` появилась в `PATH`, пользователь включает её в приложении:
   **Настройки → «Командная строка»** (создаётся симлинк `~/.local/bin/shortlinks`).
   Не предполагай иной путь к бинарю — он лежит в `Contents/Helpers`, не в `Contents/MacOS`.

## Команды

### add — создать ссылку
```bash
shortlinks add <target> [--slug <slug>] [--once | --reuse] \
  [--ttl 1h|24h|7d|never] [--password <pwd>] [-g <tag> ...]
```
- `<target>` — цель: `https://…`, `file://…`, `app-scheme://…` или путь.
- `--slug` — задать slug вручную (по умолчанию случайный).
- `--once` / `--reuse` — тип ссылки (взаимоисключающие; по умолчанию `reuse`).
- `--ttl` — срок жизни.
- `--password` — пароль, запрашиваемый перед переходом.
- `-g` / `--tag` — тег, можно повторять.
- **Вывод:** единственная строка в stdout — `sl://link/<slug>`.

Пример:
```bash
shortlinks add https://example.com --once --ttl 24h -g work
# → sl://link/k3f9qz
```

### list — показать ссылки
```bash
shortlinks list [--filter all|active|once|expired] [--tag <tag>]
```
- **Вывод:** по строке на ссылку в формате
  `sl://link/<slug>  [<kind> · <status>]  → <target>`
  где `kind` — `once`/`reuse`. Если ссылок нет — строка `Ссылок нет.`.

### resolve — узнать цель (без потребления)
```bash
shortlinks resolve <slug>
```
- **Вывод:** строка с целью ссылки. **Не** потребляет одноразовую ссылку.

### open — открыть цель (потребляет одноразовую)
```bash
shortlinks open <slug> [--password <pwd>] [--delete-on-consume]
```
- Резолвит и открывает цель в системе. Для **одноразовой** ссылки переход помечает её
  потреблённой («сгорает»); с `--delete-on-consume` она сразу удаляется.
- `--password` обязателен, если ссылка защищена паролем.

### rm — удалить ссылку
```bash
shortlinks rm <slug>
```
- **Вывод:** `Удалено: sl://link/<slug>`.

## Парсинг вывода

- **add:** возьми slug/URL из напечатанной строки `sl://link/<slug>` (последняя строка
  stdout). Передавай дальше либо полный `sl://link/<slug>`, либо сам `<slug>` в команды
  `resolve`/`open`/`rm`.
- **resolve:** stdout — это и есть цель (одна строка), бери как есть.
- **list:** разбирай строки по шаблону `<url>  [<kind> · <status>]  → <target>`.

## Выбор команды

- Нужно **только узнать цель**, не «сжигая» одноразовую ссылку → `resolve`.
- Нужно **перейти/открыть** (и допустимо потребить одноразовую) → `open`.
- Создаёшь ссылку для одноразовой передачи секрета → `add --once` (+ при необходимости
  `--password`, `--ttl`).

## Ошибки (ненулевой код возврата)

- `Ссылка не найдена: <slug>` — нет такого slug (проверь `list`).
- `Ссылка недоступна (истекла или уже потреблена)` — для `open`: TTL истёк или
  одноразовая уже использована.
- `Требуется верный --password` — ссылка защищена; повтори `open` с `--password`.

Источник истины по командам и опциям — спека `cli-interface` в репозитории
shortlinks; при изменении CLI обновляй этот навык.
